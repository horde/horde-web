Quickstart: Deploy Horde

This page gets you a working Horde Groupware instance running, from nothing, in a handful of steps. It's aimed at administrators evaluating or standing up Horde for real use. If you want to hack on Horde's own code instead, see dev.horde.org's contributor quickstart, which uses a git checkout rather than a release package.

1. Prerequisites

  • PHP 8.1 or newer (check the specific apps you plan to run for any higher per-app minimum) with the extensions typical Horde apps need: pdo plus a database driver (pdo_mysql/pdo_pgsql/pdo_sqlite), mbstring, intl, gd or imagick, and imap if you're running IMP.
  • Composer, to fetch Horde and its dependencies as released packages (no git checkout needed).
  • A database server - MySQL/MariaDB, PostgreSQL, or SQLite for small/evaluation setups.
  • A web server (Apache or nginx) with PHP-FPM, or PHP's built-in server for a quick local evaluation.
  • If you plan to run IMP (webmail): an existing IMAP/POP3 mail server to connect to - Horde does not provide one itself.

2. Get Horde

Use Composer to create a new installation from the released horde/bundle package (the standard "Horde Groupware" app set - see Applications for what's included):

composer create-project horde/bundle /srv/www/horde-dev

This fetches tagged releases of Horde and its component libraries from Packagist - not a development/git checkout - so it's the right starting point for a real deployment.

Only want specific apps rather than the full groupware bundle? You can composer require individual app packages (e.g. horde/imp, horde/kronolith) into an existing Horde base install instead of the full bundle.

3. Configure

Point your web server's document root at the installation directory's web/ (or equivalent) subdirectory, then visit the installation in a browser. Horde's setup/test screens will check your PHP configuration and let you write out the initial conf.php configuration files (database connection, session handling, mail transport, and so on) for the base horde app and each installed application.

At minimum you will configure:

  • The SQL backend (host, database name, credentials) Horde itself and most apps use for shared state (preferences, permissions, shares).
  • Per-app backends where relevant - e.g. IMP needs your IMAP/SMTP server details, Turba/Kronolith can use the shared SQL backend or an external LDAP/CalDAV source.

4. First login

Once configuration is complete, log in with the authentication backend you configured (SQL user table, IMAP, LDAP, etc., depending on your setup) and confirm the apps you installed load correctly from the Horde portal.

Troubleshooting & next steps

  • Stuck on a specific app's configuration? Check that app's page under Applications for links to its own documentation and FAQ.
  • Need help beyond what's here? See Support for community channels and paid engagement options.
  • Want to modify Horde's own code rather than just deploy it? See dev.horde.org's contributor quickstart instead - it uses a git checkout and the horde-components tool rather than a release package.
